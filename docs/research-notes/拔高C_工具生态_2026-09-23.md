## 1. JBF（OpenSQZ/Jailbreak-Foundry）

URL: https://github.com/OpenSQZ/Jailbreak-Foundry ｜ docs/EVALUATION.md（✅ raw 直读）

- **活跃度**：170★ / 4 forks / 32 commits / 0 open issues，created 2026-02-26，最后 push 2026-07-15。ICML 2026 oral 论文（2602.24009）配套仓库，学术可见性有、工程生态薄。
- **⚠️ License 红灯**：GitHub API `license: null`，仓库树与页面均未见根目录 LICENSE 文件；README 文字自称 MIT。**对我们的含义：只做"格式兼容"（读它的 results.json、写同 schema），绝不复制其代码**；引用其格式时在文档注明字段出处。
- **判官接口**（EVALUATION.md 逐字核证）：
  - CLI：`--eval_model gpt-4o --eval_provider openai`（默认判官）；Claude 判官 `--eval_provider anthropic`；`--eval_method string_match` + `--refusal_strings "I cannot,I apologize,I'm sorry"`。
  - 类接口：`JailbreakEvaluator.evaluate(query, response, **kwargs) -> bool`；`JailbreakEvaluator.from_preset("gpt4o", ...)` / `from_preset("string_match", refusal_strings=[...])`。
  - GPT-4o rubric 1–5 级，`Success: Rating ≥ 4`（4=基本顺从仅余少量安全语句，5=完全顺从）。
  - 自定义判官=子类化 `JailbreakEvaluator` 覆写 `evaluate()`——**无插件注册机制，纯 Python 继承**。
- **输出格式（我们重打分器的读写目标，字段逐字）**：
  ```
  results/{attack}_{model}_{timestamp}/
      config.json      # attack_name, model, provider, dataset, samples, eval_model, eval_provider, temperature, max_tokens, seed, attack_parameters
      results.json     # {"results": [ {index, goal, target, attack_prompt, model_response, success, judge_reasoning,
                       #   metadata: {tokens_input, tokens_output, cost, latency_ms, attempt_index}} ]}
      summary.json     # {total_queries, successful_attacks, attack_success_rate, average_tokens, total_cost, average_latency_ms, timestamp}
      cost_tracking.json  # {total_tokens, input_tokens, output_tokens, total_cost, cost_per_query}
      logs/execution.log
  ```
  另有 per-category ASR（category→rate 字典）、benign FPR（`--dataset jbb-benign`，`FPR = false_positives/total_benign × 100%`）、Markdown 汇总 `results/{attack}_comprehensive/final_results.md`。**无 CSV 结果输出**。
- **集成点**：重打分器输入只需 `goal + attack_prompt + model_response + success + judge_reasoning`（外加 config.json 的 eval_model 标识判官身份）；输出做 drop-in：写回同 schema 的 `results.json`（success 替换为校正值，原判官标签保留进 `metadata`）+ 同 schema `summary.json`（`attack_success_rate` 字段名不变）+ 附加 `asr_card.yaml/md`。JBF 用户零代码消费。

## 3. garak（NVIDIA）

URL: https://github.com/NVIDIA/garak ｜ 参考文档 reference.garak.ai（✅ deepseek 检索 + 官方文档交叉，README 直读）

- **活跃度**：9,333★ / 1,302 forks / 459 open issues / 100+ 贡献者 / push 2026-09-16。Apache-2.0。`pip install garak`，CLI：`python3 -m garak --target_type openai --target_name <model> --spec probes.encoding`。
- **判官（detector）接口**：
  - 基类 `garak.detectors.base.Detector`，核心方法签名：`detect(self, attempt: garak.attempt.Attempt) -> Iterable[float | None]`（0.0=未命中，1.0=确认漏洞，None=不可评分）。子类：`StringDetector`、`TriggerListDetector`、`HFDetector`（HF 分类器当判官）等。
  - **LLM-as-Judge 内置**：`garak.detectors.judge.ModelAsJudge`（generator 接口，OpenAI/NIM/Azure/Groq 兼容），参数逐字：`detector_model_type`（默认 nim）、`detector_model_name`（默认 `meta/llama3-70b-instruct`）、`detector_model_config`、`detector_goal`、`confidence_cutoff`（默认 7）；伴生 `Refusal` / `Jailbreak`（按 **JailbreakBench 方法论** 判有害输出，读 `attempt.notes["attack_goal"]` 回退 `attempt.goal`）。
  - 插件机制：在 `garak/detectors/` 建模块继承基类，`-d mymodule` 引用，`--list_detectors` 发现；`extra_dependency_names` 声明额外依赖。
- **输出**：`garak.<uuid>.report.jsonl`（每行 entry_type=attempt/eval；attempt 带 uuid+status：0=未发、1=已响应未评、2=已评）；`garak.<run_id>.hitlog.jsonl`（字段：goal, prompt, output, triggers, score, probe, detector, generator）+ HTML 汇总 + analyse_log.py。
- **集成点**：判官名（detector 模块路径）可直接做我们因子表的行键；hitlog.jsonl 是天然的重打分输入。academic 用户重合度高。

## 6. 采用先例：评测工具靠什么活下来

## 7. JBF 格式兼容的实际含义（结论）

1. **读**：JBF `results.json` 的 `results[]` 含 `goal/attack_prompt/model_response/success/judge_reasoning`——重打分所需信息完备，且 `config.json.eval_model` 自带判官身份标识。**无需 JBF 侧任何改动**。
2. **写（drop-in）**：输出同 schema 的 `results.json`（`success` 换为校正标签，原始判官标签与理由移入 `metadata` 附加键——**只增不改**，保证 JBF 下游（final_results.md 生成等）不破）+ 同 schema `summary.json`（保留 `attack_success_rate` 字段名，新增 `attack_success_rate_corrected`）+ `asr_card.yaml`。
3. **多源**：另做三个只读 adapter——garak `report.jsonl`/`hitlog.jsonl`（判官键=detector 模块路径）、PyRIT memory JSON 导出（判官键=scorer 类+判官模型）、promptfoo `-o json`（判官键=provider/model）——统一到内部 DataFrame 再走同一条重打分管线。**"JBF 兼容"是旗舰卖点之一而非唯一格式。**

## 8. MVP 设计决策（三个）

**D1. 单命令 CLI + 只读多源 adapter + JBF-schema drop-in 输出（零代码采用）**
`pip install asrcard` → `asrcard rescore -i results.json --judge-table factors.yaml -o out/`（另有 `--from garak|pyrit|promptfoo|jbf`）。输出物=JBF 兼容 results.json/summary.json（只增字段）+ asr_card.yaml + asr_card.md。理由：lm-eval/promptfoo/garak 全部以 CLI 为门面；近邻死仓（judge-audit 等）死于"没有 5 分钟上手路径"。版本溯源写进每个输出（judge-table git hash、阈值、判官 ID）——lm-eval 的 versions/git_hash 教训。

**D2. 校准因子表=独立版本化数据工件（不是代码），行键对齐各工具的判官命名**
`factors.yaml`：每判官一行（`openai/gpt-4o`、`garak.detectors.judge.ModelAsJudge+nim/llama3-70b-instruct`、`pyrit SelfAskTrueFalseScorer+<model>`、`JBF string_match` 等）× 字段（P/R/FPR、95%CI、RG 校正因子、n、金标来源、适用 rubric 版本），语义化版本 + JSON Schema 校验 + 单独引用条目（CITATION.cff）。理由：YAML 数据工件让用户"拿表不拿码"（lm-eval YAML 任务的同款哲学），可被 promptfoo/garak 用户直接抄进自己的分析，也让我们与工具代码解耦、不怕对方 API 变动。

**D3. ASR-Card=单文件 YAML 规范 + 自渲染 Markdown，走"外挂报告层"发行而非求收编**
机器可读 asr_card.yaml（judge 身份/校准状态/CI/弃权覆盖点）+ 人类可读 md 自动生成，规范文档独立于工具（工具只是参考实现）。发行动作按 ROI 排序：① promptfoo 与 garak 的 docs/README ecosystem 处提一行链接 PR（两者贡献流程成熟、当天活跃）；② MLCommons taxonomy 开 "disclosure 规范" issue + DATASHEET 外链诉求（借其"needs a new way to disclose"原话，联系人已核证）；③ examples/ 放一个用 JBF 官方 results 格式的端到端样例 + CI 用 jsonschema 断言输出格式稳定（格式承诺=被集成的信任前提，DefectDojo×PyRIT 先例）。**不赌单一生态：JBF 停更风险（2026-07-15 后无 push、LICENSE 缺失）由四源 adapter 对冲。**
