## 一、2609.00498 原文核证（✅ abs 页 + HTML 全文 + GitHub 仓库三重核证）

**标题**：Validity-Aware Jailbreak Evaluation for Large Language Models
**作者**：Qilong Wu, Sahil Wadhwa, Pranab Mohanty, Giri Iyengar, Varun Chandrasekaran（abs 页不显示机构；Wu 为提交人）
**日期**：v1 2026-08-31 23:57 UTC（仅一版）。**Comments: "To appear on EMNLP 2026 main"**。cs.AI，CC BY 4.0，747KB。
**URL**: https://arxiv.org/abs/2609.00498 ｜ HTML: https://arxiv.org/html/2609.00498v1
**代码**: https://github.com/Ardor-Wu/SEAV（MIT；实测 0 star / 3 commits / 1 issue，刚发布）

### 1.1 它提出了什么
- **概念**：现有越狱评估依赖"拒绝行为+语义相似+意图匹配"启发式，奖励"语言合理性（linguistic plausibility）"而非"认识有效性（epistemic validity）"。流利但事实错误/程序错误的回答会被误判为越狱成功。定义成功越狱需同时满足四性：**relevance（相关性）/ factual correctness（事实正确，检索锚定）/ ordering compliance（顺序合规）/ operational potency（操作充分性）**。区分"epistemic factuality"（求真命题）与"instructional factuality"（求可执行程序）。
- **方法 SEAV**（Sequential Epistemic and Action-Level Validation）四阶段：① 顺序化改写（把回答分解为有序步骤，识别 sequential/unordered/code-dominant/single 四型）；② 步骤有效性验证（web 检索锚定——Gemini Search grounding 或 Tavily top-5；判官 Gemini 3 Flash，辅验 GLM-5、Kimi K2.5）；③ 结构/顺序验证（对打乱步骤推断依赖边，检查原序是否满足）；④ 终判（LLM 聚合证据输出 0–1 actionability 分，>0.25 判成功）。
- **数据 SD-A**（strategic-dishonesty 诊断集）：154 条策略性不诚实回答，取自 Panfilov et al.（arXiv 2509.18058，ICLR 2026）25 个 LLM 的 MCQ 输出；OpenAI Moderation API 过滤意图，保留 141 illicit + 12 illicit/violent + 1 self-harm，固定种子每意图采样一条。
- **对照集**：JQR-Binary（n=262）控制"是否只是更严格"；**OrdSense**（137 条：original / alternative-valid / wrong-order 变体，已开源于仓库与 HF: QilongWu/OrdSense）。

### 1.2 实验范围（决定我们还剩什么空间）
- **基线判官（全部以 Gemini 3 Flash 为骨干）**：M1 LLM-as-a-Judge；M2 LLM+Web Search；M3 StrongREJECT；M4 JADES；M5 JADES+fact-check 扩展。
- **四个公开基准事后重标注**：JailbreakQR、JailbreakBench(JBB)、GPTFuzz、WildGuardMix（UltraSafety 只出现在意图/结构分析）。
- **关键数字**：SD-A 上基线假阳率 M1 57.8% / M2 57.1% / **M3 StrongREJECT 95.5%** / M4 79.2% / M5 81.8%，SEAV 降至 42.2%（最强基线 -14.9pp）；重标注把 22.1%–51.0% 的旧"成功"改判无效（JBB 51.0%、WildGuardMix 34.7%、GPTFuzz 22.1%、JailbreakQR 0.0%）；JQR-Binary 上 SEAV F1=91.2% vs M3 91.7%（证明不是单纯更严）；OrdSense 上 SEAV 独有"重排稳定 9.6% + 依赖违规敏感 61.0%"组合，M3–M5 对依赖违规近乎失明（1.5–16.9%）。检索后端（Tavily vs Gemini）与判官（GLM-5）稳健（F1≥87%）。
- **⚠️ 最重要边界：零攻击重跑**。SEAV 是纯事后重标注工作——不运行任何攻击（GCG/PAIR 等零个），不产新攻击输出；"评的是评估器而非攻击"。目标模型仅沿用 Panfilov 数据里的 25 个旧模型输出。

### 1.3 自认局限（=留给我们的官方缺口）
LLM 判官依赖（偏差/提示敏感）；face-validity 人工审计规模小；依赖推断是最不稳节点；**仅凭输出无法区分故意造假 vs 无意出错**；**单回答威胁模型（无跨回答组合攻击）**；仅英文；阈值敏感性；**对"必须拒绝"类任务（CSAM/武器合成），correctness-based 打分会低估风险**——作者自提需换 non-refusal-as-failure 规则；**detail-sufficiency 缺口**（仅 60.3% 回答细节充分）。
**自提 future work**：显式 detail-sufficiency 节点、intent-aware 评估、多语言扩展。
**仓库缺口**：SD 与 JQR-Binary 因源数据许可**未发布**；无面向任意输出的独立重打分工具（只有面向固定数据集的 pipeline + demo 脚本）。

## 三、测量惯例与判官格局

### 3.1 主流判官及其已知缺陷
- **LLM-as-judge（GPT-4o 等）**：事实上的默认（JBF 全用 GPT-4o）。缺陷：分布移位下近随机（Coin Flip, 2603.06594，6642 人工标签）；SD-A 上 M1 假阳 57.8%（SEAV）；recall 漂移 0.06–0.65、单句"Sorry, I can't"前缀即翻转 39–88%（2606.25487）；判官自身可被越狱/博弈（Bad Likert Judge, Unit42；2609.00088）。
- **StrongREJECT（NeurIPS 2024 D&B, Souly et al.）**：rubric 打分，原声称与人类一致性 SOTA（https://papers.nips.cc/paper_files/paper/2024/hash/e2e06adf560b0706d3b1ddfca9f29756-Abstract-Datasets_and_Benchmarks_Track.html ；https://github.com/dsbowen/strong_reject）。新证据：SD-A 上假阳 95.5%（SEAV）；对步骤依赖违规敏感度近乎零（1.5–16.9%）；2609.10594 中表现良好（与 JADES/HarmBench 同列前三）——判官评价互相矛盾本身即是"判官可靠性危机"的证据。
- **HarmBench classifier**：P=0.835/R=0.974（2606.25487）；GCG 白盒 70% 翻转置信真阳；验证集本为验证分类器而非 per-behavior ASR 设计；跨判官分歧实例：同集 LlamaGuard 判 29% vs HarmBench 判 68.7%（Substack 分析，🔍）。
- **LlamaGuard-3**：官方承认类别上下文局限（LG3-1B-INT4 论文 2411.17713）；对 DAN/AIM 模板攻击 Defense Success Rate 低（Promptfoo 库）；HF 独立测试标准集 FNR≈4%、对抗输入更高（🔍）。
- **JADES（CISPA 张阳组，2025-10）**：分解式 rubric（要点给分，不看开头/词藻）；2609.10594 六判官比较中综合最佳；但 SEAV 中 M4 假阳 79.2%。
- **人工标注**：金标准但贵且慢；人类一致性本身有限（AlpacaFarm 66% / MT-Bench 63%，Sage 综述引）。
- **判官间元评估（2025–2026 已有人做，勿再当空白）**：Know Thy Judge（2503.04474，Eiras et al.，被引 27——低 ASR 可能是判官弱点假象）；2609.10594（六判官同数据比较）；2606.25487（校准+对抗鲁棒）；Coin Flip（分布移位元评估）；C-SafeQA（7 判官，中文）；另有 "What Counts as Attack Success?"（OpenReview jd3XyY1Yqn 🔍）、Meta-Evaluation Collapse（OpenReview IF0L7HSs3K 🔍）、LLM-as-Judge 大规模系统评估（2606.19544 🔍）、Security in LLM-as-a-Judge SoK（2603.29403 🔍）。

### 3.2 数据集类工作与判官可靠性研究的区分（防混类）
- **strongREJECT**（2403 元年/NeurIPS 2024）：题库+配套 evaluator——一半是数据集、一半是判官；判官半身已被 SEAV/Coin Flip 直接审计。
- **WildJailbreak / WildTeaming**（arXiv 2406.18510，Ai2，262K 对，NeurIPS 2024）：**训练资源**（vanilla+adversarial 提示对）非判官研究；配套 WildGuard 模型（2406.14914）。
- **Do-Not-Answer**（arXiv 2308.13387，Wang et al.，2023）：风险评估型基准（模型该拒答的问题），非 response 级判官研究。
- 区分结论：判官可靠性研究的是"给定输出，成功判定是否可信"；数据集类研究供料。SEAV/C-SafeQA 已开始混两者（基准+判官审计），但"判官×攻击×协议"三方交叉仍无人做。

### 3.3 ASR 测量惯例现状
SoK 2605.05058 统计：**28 篇研究里 20 篇（>70%）仅用 ASR 单指标**评估攻击。惯例分五档：关键词匹配（早期，JAILJUDGE 2410.12855 指其高假阳）→ 毒性分数 → LLM-as-judge（当前主流）→ 分类器（HarmBench/LlamaGuard）→ rubric（StrongREJECT/JADES）。复现基础设施：JailbreakBench（NeurIPS 2024）、MLCommons AI Safety v0.7 jailbreak 基准（2026-02，"defensible, reproducible"）、JBF leaderboard。
**定量裂缝已确立**：GuidedBench——他基准 90%+ ASR 的方法在其上最高 30.2%；Fair-ASR——等预算下排名重排；Fragility——仅换 system prompt 摆 56pp；JBF——协议忠实复现下均值 +0.26pp；SEAV——同批输出换 validity-aware 判官即改判 22–51%。

### 4.2 为什么是"需重新框定"而非"撞死"
三根轴各自被占，但**互相之间没有焊点**，且现有结论存在一个显式悖论没人解决：
> **JBF 说攻击可忠实复现（+0.26pp）；SEAV/Coin Flip 说这些复现所依赖的判官层系统性虚高（22–51% 改判、近随机退化）。两个都对的推论是：文献的 ASR 是"可复现地错的"（reproducibly wrong）——膨胀不在攻击层，而在测量层；协议忠实复现只是忠实地复制了测量误差。**
没有人做过：同一批重跑输出 ×（多判官 ∪ validity-aware ∪ 人工金标切片）×（协议变体）的三因子分解，把"报告 ASR 与'有效 ASR'的差距"拆成可归因的三个分量。JBF 用单一 GPT-4o 判官恰好留下了这个洞。
另外四点残余空间：(a) SEAV 自认只做英文、单回答、零攻击重跑、无跨回答组合；(b) 2609.10594 是独作者预印本，其六判官比较无攻击重跑、无 validity 层；(c) Chouldechova 是概念/理论论文，没有实证 SOP 和工具；(d) 重打分工具（输入任意 (攻击,输出,判官) 输出校正 ASR+CI）不存在。

### 4.3 为什么不是"原样可做"
原主张的两处致命伤：①"量化膨胀幅度"若在常规判官下测，JBF 已给出 +0.26pp——直接反结论；②"8–15 攻击重测"的规模叙事被 JBF 的 30 攻击碾压制。必须换主轴。

### 4.4 最锋利的差异化主张（建议）
**"Reproducibly Wrong: 越狱文献 ASR 的测量层审计与三源归因"**
1. **设计**：8–12 个跨族经典攻击（GCG/PAIR/Crescendo/多轮/编码/多模态/模板等）× 4–6 目标模型，**直接复用 JBF-LIB/FORGE 模块**跑出输出（不当复现贡献，只取料）；同一批输出进三因子网格：{5–6 判官 × validity-aware 层（SEAV 开源+自建 detail-sufficiency 节点补其缺口）× 协议变体（system prompt/预算/提示形式，引 Fragility/Fair-ASR 设置）}，加 人工金标切片锚定。
2. **主结果**：文献报告 ASR → 重测常规 ASR → 有效 ASR 的逐级瀑布分解，把总膨胀拆成 判官失效分量 / 行为无效性分量 / 协议状态分量（带 CI，测量理论合规引 2601.18076）；检验核心命题"膨胀集中在测量层且随判官选择迁移 X pp"。
3. **交付**：校正测量协议 SOP（判官 P/R 报告+金标切片+对抗自检，整合 2606.25487 的建议并实证化）+ **开源重打分工具**（任意输出重打分 API，兼容 JBF leaderboard 格式——直接借其生态流量）。
4. **风险与对策**：若测量层膨胀小于 SEAV 暗示（SEAV FPR 42.2% 仍不低），"文献 ASR 大体稳健但判官间不可比"仍是一等一结论（正面对话 Chouldechova 理论）；两头都能成文，假设风险低。
5. **必须引用并显式划界的八个近邻**：SEAV、Coin Flip、JBF、Fair-ASR、Fragility、2609.10594、2606.25487、2601.18076。
